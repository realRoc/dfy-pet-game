## 二、产品定位与交付范围

对外名称仍为“大肥鱼飞行棋”，地图副标题可用“环岛日记”。这是单人、无强制失败、可随时收起的桌宠陪伴游戏。掷骰是入口，主动选择目的地、短小游戏、有利有弊的状态和永久收藏组成可玩的循环。

保持 PySide6 技术栈与现有 macOS / Windows 桌宠能力，不引入 Web 框架、不要求 GPU 3D 引擎、不把小游戏依赖到联网 API。聊天或 LLM 台词只作为已有可选能力，不能决定金币、骰子、状态或任务结果。

按阶段实现并保持每阶段可运行；这份需求包含第一与第二阶段，不能只做第一阶段就宣布全部完成。

1. 地形地图、HUD、骰子与移动、钓鱼、像素化、医院、稳定保存。
2. 森林选择事件、分支、商店、三种道具、三印章旅行目标、图鉴与旅行记录。
3. 作为未来扩展保留接口：接糖果、套圈、天气、更多地图、多人。第三阶段不属于本次必做范围，不要用随机加钱冒充这些小游戏。

## 三、美术与布局

整体是固定相机、轻俯视、2.5D 微缩玩具小岛。优先 QPainter / QGraphicsScene 搭配分层 PNG、矢量形状和缓存图层。使用哪一个由当前架构和实现成本决定，不需要迁移整个程序。

地图逻辑画布建议 1280×840，窗口默认约 1080×710，并根据可用工作区缩放。小屏幕优先保证可操作区域，提供紧凑模式。尺寸是逻辑像素，需要正确处理 Retina / DPR。不要固定一个超出屏幕的窗口。

- 地图内容约占可用区域 75%–85%。路线弯曲穿过地形，不再把所有格子贴着矩形四边。
- 湖畔、森林、像素遗迹、小镇、海边小屋各有明确地形。湖就在钓鱼格旁，医院就在治疗格旁。
- 地形台阶和坡度主要通过绘画表现，通行脚底锚点必须连续，角色不能穿房子或越水。
- 顶部薄 HUD：名称、鱼干、回合、收起与设置。左上旅行手册，可折叠。
- 下方控制托盘：背包、状态、骰子、掷骰按钮。不要用巨大标题和骰子覆盖地图中央。
- 路线上每格一个图形符号，悬停 / 键盘聚焦显示名称与效果。蓝色钓鱼、紫色像素、薄荷色医院、金色宝箱还应有不同图形 / 纹理，不能只靠颜色。
- 背景装饰、事件石板、角色、前景遮挡、粒子和 HUD 分层。脚底决定角色深度，同深度按明确次序排序。
- 主要文字深蓝，面板奶油白，背景低饱和蓝绿。建议起点色板：#F8F2E6、#284D79、#78BBD0、#98BDA1、#A18BC8、#E5B96A。
- 文字由程序排版，不把生成图里的文字烘焙到按钮。提示气泡不能盖住当前主按钮。
- 中文正文建议 14–16 逻辑像素；主交互点击区域目标至少 40×40；低空间下使用聚焦详情代替把文字挤小。
- 三张概念图都不是素材图集。正式地图背景不应包含可交互石板、角色、文字或 HUD；这些独立绘制。无分层美术时，先用细致的代码形状与纹理构建完整场景，写清楚哪些美术还可替换。

骰子：奶油白有倒角的立方体、深蓝凹点、统一光源、柔软落影。动画可用投影多边形和缓动模拟体积，最终面必须清晰显示本次结果。6 个结果点位由代码固定绘制；不要裁概念图里的骰面当结果。

参考动画时序：按下压缩 100ms → 弹起旋转 450ms → 落地回弹 180ms → 读点数 180ms。公平 1–6，掷骰开始只生成一次真实结果，装饰动画不改变结果。减少动态效果模式可压缩动画且不晃动窗口。

保留角色三视图、方向切换、侧面镜像、逐格抛物线跳动与落地挤压。每格跳约 180–260ms，可加速。清楚区分“当前所在格”和“本回合将到达格”。奖励从事件附近飞向 HUD，数值只结算一次。

## 五、回合流程与交互约束

使用明确状态机，例如：

`IDLE → ROLLING → PREVIEW → MOVING → [ROUTE_CHOICE / STOP_CHOICE] → EVENT / MINIGAME → RESOLVE → IDLE`

- PREVIEW 可使用步数调整道具一次，再确认移动。没有道具也保留一个清楚的移动确认入口，可用空格。
- ROLLING、MOVING、事件结算时防止重复掷骰、重复按键穿透、重复领奖。
- 路口和停靠选择都由按钮 / 键盘显式推进，不以后台计时默认替玩家选择。
- `turn_id` 在开始掷骰时递增一次，跳过小游戏不额外产生回合。
- `Space/Enter` 操作当前主控件；弹层存在时先由弹层消费按键。方向键或 Tab 导航，焦点可见。
- Esc 优先关闭可取消的详情 / 背包；小游戏中打开暂停与“放弃本次”入口；没有弹层时收起棋盘返回桌宠，不退出程序。
- 收起棋盘、失焦和隐藏时小游戏暂停，不能后台继续倒计时判失败。
- 掷骰 / 移动中收起时冻结会话。重开窗口可从同一活动状态继续。程序退出前必须保存可恢复的回合信息，不能重新随机骰子、重复工资或重复奖励。
- 只在指定空白区域 / 拖动柄拖窗口，不能把按按钮或选择路径误判为拖动。

## 六、钓鱼小游戏

入口：m02 自然落点或主动停靠。显示湖、鱼影、码头、浮漂与当前角色，游戏 UI 贴近湖面，保留明确退出 / 跳过入口。

每局最多 3 次尝试，总计活动时间不超过 15 秒：

1. 每次等待约 0.6–1.2 秒后出现咬钩提示。
2. 在可见时机条中，指针以固定速度移动，目标窗口宽约 30%。目标位置本次尝试开始时固定，不在玩家点击时改变。
3. 玩家点击“收竿”或按空格，指针位于目标窗口为成功。过早点击 / 超时算本次失败，不罚钱。
4. 3 次结束、提前跳过或放弃后进入唯一结算。没有隐藏手速加成，不连点获益。

奖励 `1 + 成功次数` 鱼干，范围 1–4。直接跳过 / 放弃按当前已完成成功次数结算，最低 1。点击跳过即锁定本局，不可回到同局重新领奖。

图鉴是永久收藏，与鱼干分开记录。普通模式至少成功一次，按配置抽一个普通鱼种；无需模拟背包卖鱼。像素状态且至少成功一次时，若尚无像素鱼，本次必定获得第一条像素鱼，代替本次普通收藏。已有像素鱼时每局 20% 记一次像素鱼收藏，否则普通鱼。收藏不额外发鱼干。

首次完成一局且至少进行过一次有效尝试，授予湖畔印章，成功次数可以为 0；一进入就跳过不授章。开发模式允许固定 RNG 与模拟时间验证。

## 七、像素化状态与治疗

像素状态字段至少包含 `active`、`starts_remaining`、`acquired_turn_id`，放在共享游戏模型中。

- 落在 m18 或 b01 时授予像素旅行印章。没有像素状态则申请施加像素状态，初始 `starts_remaining=3`。
- 已有状态时保留当前剩余次数，不刷新、不叠加，吐槽“已经够像素了”。护盾也无需消耗。
- 角色精灵先缩小到低分辨率，再用最近邻放大；复用正侧背三视图，缓存每个尺寸与朝向的像素版本。
- 棋盘、桌宠共用状态，收起棋盘后桌宠继续以像素角色显示。菜单、聊天文字和业务逻辑不受渲染状态污染。
- 装饰边框、头像、局部地形可像素化，按钮 / 文字 / 焦点 / 点击区必须保持清晰一致。不得把整个 QWidget 截图缩小再放大导致无法操作。
- 真正经过起点时，每次扣 1，扣到 0 清除。只有获得状态之后的有效经过才算，恢复存档与动画重放不能多扣。
- 状态不扣步数、不跳回合、不降低小游戏难度。唯一玩法差别是像素专属收藏与台词。
- 状态条持续显示“像素化 · 还需经过起点 N 次”。点击可看恢复说明。

三种恢复：

1. 在 m20 停靠 / 落点，医院提供“3 鱼干治疗”和“保留像素状态”；支付确认后扣费并立刻清除。若余额不足 3，显示“援助治疗 · 免费”，不产生债务、额外奖励或强制失败。健康时不扣费。
2. 有解像素糖时，可在 IDLE 或 PREVIEW 从背包使用，一次消耗一颗；健康时按钮禁用且不消耗。使用不消耗掷骰前道具以外的额外回合。
3. 经过起点 3 次自然恢复。

“去医院”在状态说明卡中只定位医院并显示路线距离，不能远程治疗或瞬移。m18 后 2 步就是 m20，医院可路过主动停靠。开新旅程赠一颗解像素糖，减少初见状态时的挫折。

## 八、经济、道具与事件

只有一种可消耗货币：小鱼干。新旅程 6 鱼干，初始一颗解像素糖，其他道具为 0。余额不能小于 0。

| 来源 / 消耗 | 数值 |
| --- | --- |
| 每次有效经过起点 | +3 |
| supply 落点 | +1 |
| 钓鱼 | +1 至 +4 |
| 森林安全采集 | +1 |
| 森林冒险采集 | 成功 +3；失败 +0 与轻恶作剧 |
| chest 落点 | 每圈每个宝箱首次 +2；同圈再次落到仅台词 |
| 医院治疗 | -3；不足 3 为免费援助 |
| 步数 ±1 道具 | 商店价格 3 |
| 解像素糖 | 商店价格 2 |
| 护身泡泡 | 商店价格 3 |

背包三种道具，每种最多 3 件。每圈商店每种道具限购 1 件，库存按真实起点经过后的 `lap_id` 更新。满背包 / 售罄 / 余额不足都不能扣费。

每个掷骰回合最多主动使用 1 件道具：可以在 IDLE 使用糖或泡泡，也可等 PREVIEW 使用糖、泡泡或步数调整。使用后其余主动使用入口本回合禁用；进入下一次 IDLE 才刷新额度。没有生效的禁用操作不消耗额度。

- **步数 ±1**：只在 PREVIEW 使用，玩家选择 +1 或 -1，最终步数限制 1–6；若选择会超界，不消耗道具，不允许用 +1 给 6 保持原值却消耗。一次使用后更新路线预览。
- **解像素糖**：上述恢复规则。
- **护身泡泡**：赋予一次持久护盾，直到抵挡一次“新施加的像素状态”或“小恶作剧”。护盾最多 1 层，有护盾时不能再使用。生效时只消耗护盾，仍授予像素地点的访问印章。医院 / 吃糖不消耗护盾。

森林 m10 提供两个选项：安全采集 +1；冒险采集 50% +3、50% +0 并触发小恶作剧。首次选择任意一个即授予森林印章；未选择直接退出不授章。随机在确认选择时只抽一次。

小恶作剧只有一个初版效果：丢 1 鱼干，最低扣到 0，配一次可爱的表情，不跳过下一回合。护盾可完全挡下。m21 mystery 各 50% 为纯台词 / 小恶作剧；不产生事件套事件。

rest 和 story 为 1–2 秒可跳过的表情 / 台词，不扣钱、不跳回合。现有暂停回合恶作剧移除。宝箱按 `(node_id, lap_id)` 记录领奖；每一次交易和奖励有唯一事务 ID，避免保存、重复点击、动画回调导致重复。

## 九、旅行目标、收藏与回顾

本次旅程记录 3 个印章：湖畔、森林、像素。条件分别见前文。集齐后只授予一次本旅程完成奖励：一个小屋摆件（首次）、永久完成次数 +1，以及一张可关闭的旅行回顾卡。继续散步，不强制结束。

鱼图鉴、摆件解锁与完成次数是永久档案；位置、鱼干、道具、像素状态、护盾、lap_id、印章是当前旅程档案。重新开始需明确区分这两部分；保留现有永久收藏。重复解锁摆件只增加完成记录，不反复变现。

旅行日志最多保留最近 100 条结构化事件，包含 event_id、turn_id、node_id、event_type、结果与状态。界面用模板生成 2–3 句回顾，例如“去了湖边，钓到第一条像素鱼，最后带着方块脸回了家”。不要把未发生的剧情编成事实。

## 十、模型、存档与实现边界

将纯规则与绘制逐步分开，建议按实际需要组织为 game_state、map_config、events、status、minigames、renderer 等模块，不必照抄命名。关键要求：模型可在无窗口情况下验证；UI 只发命令和消费已结算结果，不在 paintEvent 中随机或加钱。

核心状态至少有：schema_version、turn_id、phase、node_id、remaining_steps、roll_result、planned_path / chosen_edges、lap_id、coins、inventory、item_used_this_turn、pixel_status、shield、journey_stamps、permanent_collection、chest_claims、shop_stock、pending_event、applied_transaction_ids。

持久化策略：

- 与 common.py 已有配置兼容，旧 board_pos 映射到 `mXX`，旧 coins/turn 保留；新增字段用明确默认值。
- 老档案升级不重新赠送初始鱼干或糖。新旅程才给初始资源。
- 新增游戏档案最好独立命名空间 / 文件，不改写已有 ds_api_key 等桌宠设置。禁止把配置或 key 打印到日志、截图或测试输出。
- 原子写入：同目录临时文件 + 替换；保留一个可恢复备份，坏档案给可理解提示并尽量恢复永久收藏。
- 事件开始生成 pending_event，随机结果一旦生成就保存；结果与资源修改作为同一次原子提交写入。领奖动画只展示提交后的变化。
- 移动每条边完成时，起点奖励 / 状态扣次 / 当前节点 / 剩余步数一起保存。恢复后不能重放该条边的副作用。
- 程序退出保存已经确定的骰子、路径与待结算事件。小游戏中退出保存当前尝试结果与剩余活动时间；重开从暂停态继续。不能关闭窗口刷新结果。
- 不在 paintEvent 读写磁盘或重建所有 QPixmap。静态地形缓存，环境层低频更新，角色与骰子按需重绘，隐藏窗口暂停无用计时器。
- 核心循环不使用 time.sleep 阻塞 Qt 线程。保留现有网络操作的线程边界。
